# IA open source en pratique : comment Biscuits IA aide les associations et TPE à reprendre la main

L'IA générative est devenue indispensable. Mais pour une association, une mairie, une TPE ou un collectif, **déléguer toute son intelligence à ChatGPT, Claude ou Gemini** pose vite question : où vont mes données ? combien ça coûte à grande échelle ? que se passe-t-il si le service ferme ?

## 🤔 Pourquoi parler d'IA open source en 2026 ?

Pendant des années, l'IA de pointe était l'apanage de quelques géants américains (OpenAI, Google, Anthropic). **Ce n'est plus le cas.**

### Une bascule historique

En 2023-2024, Meta publie Llama 2 puis Llama 3 en open source. Mistral AI, startup française, sort Mistral 7B puis Mixtral. Alibaba publie Qwen, Microsoft Phi, Google Gemma, DeepSeek DeepSeek-V3.

Résultat : en 2026, **les meilleurs modèles du monde sont disponibles en open source**, avec des licences qui permettent une utilisation commerciale, parfois sans restriction majeure.

### Trois motivations concrètes

**1. La confidentialité.** Une association qui manipule des données d'adhérents ne peut pas se permettre d'envoyer chaque échange sur des serveurs américains. L'IA open source déployée sur un cloud européen résout ce problème.

**2. L'économie.** À grande échelle, les API commerciales coûtent cher. Pour une association qui fait 50 000 requêtes par mois, l'open source devient rentable en moins d'un an.

**3. L'autonomie.** Vous n'êtes plus dépendant d'un fournisseur qui peut changer ses conditions, augmenter ses prix, ou fermer son service. Votre IA vous appartient.

<Callout type="warning" title="L'open source n'est pas magique">
Avoir accès au code d'un modèle ne signifie pas savoir l'exploiter. Le déploiement, le fine-tuning, la mise en production, la maintenance : tout cela demande des compétences. C'est précisément **le fossé que Biscuits IA aide à combler**.
</Callout>

## 🆚 Open source vs API propriétaire : la décision structurante

C'est la question que toute organisation doit se poser. Voici un arbre de décision clair.

### Les critères de choix

**Choisissez l'API propriétaire (ChatGPT, Claude) si :**
- Vous faites moins de 10 000 requêtes par mois
- Vous n'avez pas de données sensibles
- Vous voulez un résultat immédiat sans infrastructure
- Vous n'avez aucune compétence technique en interne
- Vous êtes prêt à payer un abonnement

**Choisissez l'open source si :**
- Vous manipulez des données personnelles (adhérents, usagers, patients)
- Vous avez plus de 50 000 requêtes par mois
- Vous avez un projet sur plusieurs années
- Vous voulez personnaliser le modèle sur votre domaine
- Vous avez (ou pouvez acquérir) des compétences techniques
- Vous voulez maîtriser vos coûts à long terme

**Choisissez une approche hybride si :**
- Vous utilisez l'API pour les usages non sensibles
- Vous déployez l'open source pour les usages critiques
- Vous voulez bénéficier des deux mondes

### Le calcul économique réaliste

Pour une association qui fait 100 000 requêtes par mois :

| Solution | Coût mensuel estimé |
|---|---|
| OpenAI API (GPT-4o-mini) | 150 - 500 € |
| Mistral API (Mistral Small) | 100 - 300 € |
| Auto-hébergement open source | 80 - 200 € (serveur cloud) + temps humain |
| Auto-hébergement sur poste existant | 0 € + temps humain |

**Le point de bascule** se situe généralement autour de **50 000 à 100 000 requêtes par mois**. En dessous, l'API est souvent plus rentable. Au-dessus, l'open source devient intéressant.

<Callout type="tip" title="La main d'œuvre, le vrai coût">
Le calcul ci-dessus oublie le principal : le **temps humain** pour mettre en place, maintenir, faire évoluer. Comptez 1 à 5 jours-homme pour la mise en place, puis 0.5 à 1 jour par mois pour la maintenance. C'est là que l'accompagnement Biscuits IA fait la différence.
</Callout>

## 🛠️ Le guide pratique : déployer une IA open source

Vous avez décidé de vous lancer. Voici les étapes concrètes, telles que nous les menons avec les structures accompagnées.

### Étape 1 : Définir le cas d'usage (1 semaine)

Avant de toucher au code, on clarifie :
- **Quel problème** l'IA doit-elle résoudre ?
- **Quels utilisateurs** vont s'en servir ?
- **Quelles données** seront traitées ?
- **Quel niveau de qualité** est acceptable ?
- **Quelles contraintes** légales, budgétaires, techniques ?

Sans cette étape, on se retrouve à déployer un modèle pour rien.

### Étape 2 : Choisir le bon modèle (1 à 2 semaines)

On évalue 2 à 3 modèles candidats sur des cas concrets :
- Qualité des réponses sur vos données typiques
- Performance en français
- Temps de réponse (latence)
- Coût en ressources (RAM, GPU)
- Compatibilité avec votre stack technique

On utilise un **jeu de test de 50 à 100 cas réels** pour comparer objectivement. C'est notre méthode d'évaluation chez Biscuits IA.

### Étape 3 : Préparer l'infrastructure (1 à 3 semaines)

### Étape 4 : Déployer le modèle (1 à 2 semaines)

Les outils modernes rendent le déploiement accessible :

- **Ollama** : la référence pour faire tourner un LLM en local, ultra simple
- **LM Studio** : interface graphique pour tester et utiliser des modèles
- **vLLM** : serveur de production haute performance
- **llama.cpp** : moteur bas niveau pour optimiser les performances
- **Hugging Face Transformers** : la bibliothèque de référence

Pour une première mise en œuvre, **Ollama** est imbattable : une commande pour télécharger un modèle, une autre pour le faire tourner, une API REST exposée automatiquement.

```bash
# Installation d'Ollama sur Linux
curl -fsSL https://ollama.com/install.sh | sh

# Téléchargement et lancement de Llama 4 8B
ollama run llama4:8b

# Test direct dans le terminal
Pose une question : `Explique-moi le RGPD en 3 phrases`
```

Pour un usage en production, on passe par **vLLM** ou **Ollama + Open WebUI** (interface web) pour avoir une application utilisable par des non-techniciens.

### Étape 5 : Connecter à vos outils (2 à 4 semaines)

L'IA seule n'a que peu d'intérêt. La valeur vient de son **intégration** à vos outils existants :
- **Site web** : chatbot d'assistance, FAQ augmentée
- **Messagerie** : rédaction d'emails, résumé de fils de discussion
- **GED / SharePoint** : recherche sémantique dans vos documents
- **CRM** : qualification des demandes entrantes
- **Outils métier** : génération de rapports, comptes-rendus

On utilise des frameworks d'orchestration comme **LangChain**, **LlamaIndex**, ou **Flowise** pour chaîner le LLM avec vos données et vos APIs.

<Callout type="warning" title="Le RAG, indispensable pour les usages professionnels">
Pour qu'une IA connaisse vos documents, votre vocabulaire, vos processus, on ne la fine-tune pas (coûteux, complexe). On utilise le **RAG** (Retrieval-Augmented Generation) : l'IA va chercher les bonnes informations dans vos documents avant de répondre. C'est la méthode standard en 2026, et elle fonctionne remarquablement bien.
</Callout>

### Étape 6 : Sécuriser, monitorer, améliorer (continu)

Une IA en production demande une **gouvernance** :
- Logs des requêtes et réponses (traçabilité RGPD)
- Filtrage des contenus dangereux (jailbreak, prompt injection)
- Monitoring des dérives (hallucinations, biais)
- Mise à jour régulière des modèles
- Formation continue des utilisateurs

## 🛡️ Les challenges techniques (et comment on les gère)

Soyons honnêtes : déployer une IA open source en autonomie n'est pas trivial. Voici les principaux défis.

### Le défi n°1 : Les ressources matérielles

Faire tourner un LLM demande de la **RAM** et idéalement un **GPU**.

| Modèle | Taille | RAM minimum | GPU recommandé |
|---|---|---|---|
| Phi-4 (3.8B) | ~3 Go | 8 Go | Optionnel |
| Llama 4 8B | ~5 Go | 10 Go | Recommandé |
| Mistral Small | ~14 Go | 16 Go | Fortement recommandé |
| Llama 4 70B | ~40 Go | 48 Go | Nécessaire |
| Mistral Large 2 | ~120 Go | 128 Go | GPU pro obligatoire |

Pour les associations, on recommande généralement de **commencer avec un modèle 7-8B** (Phi-4, Llama 4 8B, Mistral Small) sur une machine modeste, puis de monter en taille si nécessaire.

### Le défi n°2 : La performance

Un modèle open source sera souvent **2 à 5 fois plus lent** qu'une API propriétaire sur la même machine. Pour les usages interactifs, il faut :
- Choisir un modèle adapté à votre hardware
- Optimiser la quantification (Q4, Q5, Q8)
- Prévoir un GPU si vous voulez du temps réel
- Accepter une latence légèrement supérieure

### Le défi n°3 : La qualité

Un modèle 8B sera moins performant qu'un modèle 70B. Pour compenser :
- Utiliser le **RAG** pour enrichir le contexte
- Faire du **prompt engineering** soigné
- Évaluer régulièrement la qualité
- Avoir un humain dans la boucle pour les cas critiques

### Le défi n°4 : La sécurité

Une IA mal configurée peut fuiter des données, générer des contenus dangereux, ou être manipulée par prompt injection. On met en place :
- **Filtrage des entrées** (détection de tentatives de jailbreak)
- **Filtrage des sorties** (contenus dangereux, données personnelles)
- **Sandboxing** (isolation du modèle)
- **Logs et audit** (traçabilité)

<Callout type="error" title="L'erreur classique du débutant">
Beaucoup de structures achètent un GPU à 5 000 € avant d'avoir testé si le modèle convient à leur besoin. **Testez d'abord sur du matériel modeste ou dans le cloud**, validez l'usage, puis investissez dans l'infrastructure dédiée si nécessaire.
</Callout>
